## 1. What was compared, and why

The Random Forest used throughout Stage 2 (`train_model.py`) had never been measured against alternatives - it was chosen qualitatively (ADR-007). This run compares four model families - **Ridge**, **Decision Tree** (max_depth 10), **Random Forest** (a 3x3 grid of n_estimators in {100, 200, 300} x max_depth in {None, 10, 20}), **HistGradientBoosting** - plus a **hybrid** (Ridge carries the level, a RandomForest fits Ridge's residual), each under three target modes: **raw** (predict Vehicles directly), **diff** (predict Vehicles - lag_168, add lag_168 back), and **ratio** (predict Vehicles / roll_168_lag168, multiply back). **39 model configurations** were evaluated in total, plus the seasonal-naive baseline (lag_168) for reference - 40 rows in the validation table.

## 2. Selection rule

Stated and fixed before any validation number was seen: Lowest OVERALL_excl_West validation MAE; if any configuration is within 0.1 MAE of the best, take the simplest configuration in that tied group instead (Ridge < DecisionTree < RandomForest < HistGradientBoosting < Hybrid; within RandomForest, fewer trees and shallower depth is simpler; raw target < diff target < ratio target). This rule was fixed before the validation grid was run and applied mechanically to the results - selection used validation only, test was not consulted.

Selection used validation only: inner-train (2015-11-15 00:00:00 to 2016-10-08 23:00:00, 31584 rows) to fit, validation (2016-10-09 00:00:00 to 2016-12-31 23:00:00, 8064 rows) to score. Test (2017-01-01 00:00:00 to 2017-06-30 23:00:00, 17376 rows) was not touched until section 5.

## 6. Findings

- The hybrid did **not** beat Random Forest on validation: best Hybrid (Hybrid_Ridge_RF200depth10, target=raw) scored 4.245 MAE against best RandomForest (RandomForest_n300_depth10, target=diff) at 4.073 MAE. This is reported as a result, not a footnote: two-stage machinery did not earn its complexity here.
- **Ridge** with the **ratio** target was the worst of all 39 model configurations compared (OVERALL_excl_West MAE=8.732), driven by North alone reaching 18.021 MAE under that transform - Ridge's linear extrapolation on a ratio target overshoots badly on North's strong trend.
- The **diff** target's best configuration (4.073 MAE) beat both the best **raw** configuration (4.240 MAE) and the best **ratio** configuration (4.307 MAE).
- Under the **static** protocol the selected model **lost** to the naive baseline on test: 6.69 vs 5.22 baseline MAE.
- Under the **rolling** protocol it **beat** the baseline overall: 4.87 vs 5.22 baseline MAE.

## 7. Limitations

- The rolling protocol does **not** beat the baseline on every road. North is worse (6.49 vs 6.30 baseline), and South is effectively tied (2.80 vs 2.88 baseline). The overall win is driven mainly by East (5.31 vs 6.49 baseline). This is stated explicitly and not rounded away.
- Four test evaluations informed selection decisions (ADR-014, the corrected re-run, this file's prior 2-target-mode version, and this run's static protocol), plus one rolling protocol comprising 26 refits on which no selection was performed.
- ADR-016 recorded a seed-to-seed noise floor of sd=0.0119 MAE (5 random seeds, 300 trees, full 14-feature set, original validation split). The margin (0.351 MAE) is about 30x that noise floor. This is not a like-for-like significance test - ADR-016's figure is seed-to-seed variance on the original validation set under an unchanged configuration, while this margin is a single fixed-seed comparison between two different TEST-time protocols - but a margin this many multiples of the recorded noise floor is unlikely to be noise.
